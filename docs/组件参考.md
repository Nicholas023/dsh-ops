# 组件参考
六个组件分别发布什么工具、参数是什么、需要什么权限。
---

## 组件总览

| 配置行 `name` | 介绍 | 默认 | 发布的工具 |
| --- | --- | --- | --- |
| `dsh-ops/shell` | 将默认终端改为 bash，以及 bash 覆盖不到时提供 PowerShell 7 | 开 | `ops_bash`；宿主 `pwsh` 使用随包 PowerShell 7 |
| `dsh-ops/file` | 更快、更高性能、输出更精简更省 token 的 Rust 文件检索 | 开 | 四个文件工具 |
| `dsh-ops/ptc` | 独立 Rust 安全批处理和有界结果引用，仅纯 PTC 会话加载 | 关 | `ops_batch`、`ops_result` |
| `dsh-ops/panel` | 数据采集，开关默认关：新对话写入 `<cwd>/.dsh-ops/panel/<sessionId>.json` 与读取它的 `panel.html` | 行开，`capture: false` | 无；见[配置参考](配置参考.md) |
| `dsh-ops/tui` | 当前会话的只读 OPS 侧栏 | 关 | 无；见 [侧栏说明](tui-panel.zh.md) |
| `dsh-ops/hide-official` | 只隐藏 shell/file/ptc 三面中已有 OPS 等价物的官方工具；其余保留可见并警告 | 关 | 无 |

原 `dsh-ops/background` 组件（FastCtx 后台任务：`ops_run`、`ops_run_background`、`ops_job_output`、`ops_job_list`、`ops_job_kill`）已移除。仍写着它的 profile 行会作为空操作加载：接受任意配置、不发布任何工具，只记录一条警告提示可删除该行。

## 工具总表

| 工具 | 用途 | 完全权限要求 |
| --- | --- | --- |
| `ops_inspect_local_file` | 有界 UTF-8 文本行与 hex | 无命令权限门¹ |
| `ops_grep` | Rust 正则搜索、多文件过滤、计数/摘要 | 无命令权限门¹ |
| `ops_glob` | 多模式找路径，支持排除 | 无命令权限门¹ |
| `ops_replace` | 跨文件字面文本批量替换；精确编辑仍用宿主 edit | 无命令权限门¹ |
| `ops_bash` | 优先的通用 bash 命令执行器；短命令用 `command`，长脚本用 `script_path` | 受限模式经 DSH 沙箱；Windows x64 使用匹配的私有 IPC 副本 |
| `ops_batch` | 预检并执行 copy / move / remove，带审计与恢复 | 见 PTC 说明 |
| `ops_result` | 有界结果引用：写入、分页、释放 | 见 PTC 说明 |
| 宿主 `pwsh` | 使用随包 PowerShell 7 的 Windows 原生操作 | 沿用宿主策略 |

¹ **固定文件操作遵循 DSH fs-sandbox 同类的可信操作权限检查，不执行模型代码。** 所有模式允许 OS 可读路径的读取；read-only 拒绝替换（含其 dry run），workspace-write 允许工作区及本会话私有临时目录内替换，full-access 不额外限制写路径。通过宿主 subprocess 执行固定 Rust worker，保留无链接遍历、预算及 CAS；Bash/run_code 仍通过 OS 沙箱，绝不在失败后裸执行。Windows 启动前只为当前用户拥有的工作区根准备目录自身 WRITE_OWNER 并备份 DACL，不递归、不改所有者。该准备步骤以当前用户身份、在沙箱约束生效之前运行包内自带的脚本，仅在工作区内修改模式下执行，并传 `-ExecutionPolicy Bypass`（组策略仍优先）。

## `dsh-ops/file` —— 文件工具

全部文件工具都以 DSH 会话 cwd 为基准解析相对路径，只接受一个 `path`，不提供 `root`、`workspace`、`cwd` 或 `file_path` 别名。全部为 UTF-8 优先且有界输出；glob 与 grep 不遍历符号链接、junction、重解析点、隐藏文件和 `.git`。

宿主提供 `fs` 服务时，`ops_inspect_local_file` 的读取与 `ops_replace` 的实际写入会像宿主 `read`/`edit` 一样登记到宿主的「先读后改」观测表（`fs/observed`）：用 OPS 读过的文件可直接用宿主 `edit`，OPS 写过之后宿主也不会把它误判为外部改动。`ops_grep`、`ops_glob` 与 `dryRun` 不登记。

### `ops_inspect_local_file`

读取有界 UTF-8 文本行，或某个路径的 hex 视图。目录会被拒绝——请改用 `ops_glob` 或 `ops_grep`。

| 参数 | 类型 | 说明 |
| --- | --- | --- |
| `path` | string | 相对 DSH 会话 cwd 解析 |
| `offset` | integer ≥ 1 | 起始行 |
| `limit` | integer 1–10000 | 最多返回行数 |
| `encoding` | `utf-8` | 编码 |
| `view` | `text` \| `hex` | 视图模式 |

### `ops_glob`

在 `path` 下查找普通文件。`pattern` 是 glob **数组**，按相对 `path` 的路径逐段匹配（ASCII 不区分大小写），例如 `["**/*.md","!vendor/**"]`：`*.md` 只匹配顶层，`**/*.md` 匹配任意深度；`!` 前缀表示排除，且至少需要一个正向条目。传单个字符串会被拒绝；没有 `include` 字段。

| 参数 | 类型 | 说明 |
| --- | --- | --- |
| `path` | string | 搜索根 |
| `pattern` | string[]（必填，≥1） | glob 模式 |
| `outputMode` | `paths` \| `details` | 输出形态 |
| `sort` | `path` \| `modified` | 排序 |
| `offset` | integer | 分页起点 |
| `limit` | integer 1–10000 | 最多返回条数 |

### `ops_grep`

用 Rust regex 在 `path` 下搜索 UTF-8 文件，输出有界，支持分页与行上下文。`pattern` 是**一个**正则字符串；用 `glob`（与 `ops_glob` 相同语法的数组）限定文件，**没有 `include` 字段**。`glob` 可以只有排除项（表示「除此之外全部」）；`path` 指向单个文件时忽略 `glob`。

| 参数 | 类型 | 说明 |
| --- | --- | --- |
| `pattern` | string（必填） | Rust 正则 |
| `path` | string | 搜索根 |
| `glob` | string[] | 限定文件 |
| `outputMode` | `files_with_matches` \| `content` \| `count` \| `summary` | 输出形态 |
| `caseInsensitive` | boolean | 忽略大小写 |
| `lineNumbers` | boolean | 显示行号 |
| `beforeContext` / `afterContext` | integer ≤ 32 | 上下文行数 |
| `multiline` | boolean | 跨行匹配 |
| `offset` / `limit` | integer 1–10000 | 分页 |

### `ops_replace`

在 `path` 下执行确定性的 UTF-8 替换。`pattern` 是**字面文本，不是正则**；`glob` 规则同 `ops_grep`。`dryRun` 只观察；写入使用内容 revision 校验与原子替换。read-only 会话会被拒绝。

| 参数 | 类型 | 说明 |
| --- | --- | --- |
| `pattern` | string（必填） | 字面文本 |
| `replacement` | string（必填） | 替换内容 |
| `path` | string | 作用根 |
| `glob` | string[] | 限定文件 |
| `maxReplacements` | integer 1–100000 | 替换数硬上限 |
| `dryRun` | boolean | 不产生写入 |

### 结果与错误

- **文件工具、`ops_batch`、`ops_result` 不抛异常**：失败以值返回，`status` 为 `"error"` 或 `"rejected"`（权限拒绝），并带 `error.code` / `error.message` / `error.nextAction`；成功为 `"completed"`（`ops_batch` 另有 `planned` 等状态）。在 PTC 中只包 `try/catch` 会漏掉这些失败，要检查 `status`。
- **`ops_bash`**：命令结果以值返回，含 `status`（`completed` 仅表示退出码 0 且无错误/权限拒绝/信号/超时，否则为 `failed`）、`exitCode`、`stdout` / `stderr`、`error`、`permission`。只有**参数无效**或**执行器不可用**时才抛出（PTC 中为 `ToolCallError`）。
- 宿主工具（`read` / `write` / `edit` / `pwsh` 等）失败时抛 `ToolCallError`。

## `dsh-ops/ptc` —— 原生批处理与结果引用

组件默认启用，仅纯 PTC 会话发布工具；保留用户在 profile 中明确关闭的选择。

### `ops_batch`

预检并校验 copy / move / remove。

| 参数 | 类型 | 说明 |
| --- | --- | --- |
| `action` | `plan` \| `run` \| `resume`（必填） | 动作 |
| `root` | string | 默认会话 cwd；显式给出时必须是绝对路径（相对 root 在 preflight 被拒，返回 `INVALID_ARGUMENT`） |
| `operations` | 数组，≤512 项 | 每项 `op`（`copy`/`move`/`remove`）+ `path` + `to` |
| `operationsRef` | string | 引用已存的操作清单 |
| `protect` | string[]，≤128 项 | 保护路径 |
| `id` | string | `resume` 时指定既有计划 |

> `action=plan` 需要 `operations`，只产生无副作用的审计计划；执行该计划要传 `action=resume` 加 `id`（**不要改成 `run`**）。`action=run` 需要 `operations` 并立即执行。操作使用相对 `/` 路径，不覆盖、不跟随链接。计划 root 与会话工作区 root 不同时，分页 `detailsRef` 要传同一个 `root`，否则返回 `NOT_FOUND`。

### `ops_result`

会话自有的有界结果引用：写入对象行、按顶层 `equals`/`fields` 与数量/字节预算分页、释放结果。24 小时过期。job 审计只读。引用是观察结果，从不是权限来源。

| 参数 | 类型 | 说明 |
| --- | --- | --- |
| `action` | `put` \| `page` \| `release`（必填） | 动作 |
| `items` | 对象数组，≤10000 项 | `put` 的数据行 |
| `root` / `id` | string | 作用根与结果 id |
| `offset` | integer ≥ 0 | 分页起点 |
| `limit` | integer 1–512 | 每页条数 |
| `maxBytes` | integer 512–65536 | 每页字节预算 |
| `fields` | string[]，≤32 项 | 投影字段 |
| `equals` | object | 顶层过滤条件 |

## `dsh-ops/shell` —— 终端与 shell

执行顺序：**工具包 → bash → PowerShell 7**。

- `ops_bash`：优先的通用命令执行器。短命令用 `command`，长脚本用 `script_path`。
- 宿主 `pwsh`：Windows 原生操作，使用随包 PowerShell 7。

“默认终端改为 bash”指模型提示优先使用 `ops_bash`，**不修改系统默认终端、PATH 或宿主原有 shell 工具名称**。Shell 组件开时，通过官方配置生命周期临时指定 `pwsh-sandbox` 的 PowerShell 7 路径；关时按执行器最新原配置恢复，不写 profile 配置。执行器配置切换不代表取消已在运行的宿主命令。

模型侧看到的路由表由插件按其实际发布情况渲染：

```
# Shell routing: bash → PowerShell 7

| Task | Tool |
| --- | --- |
| Text / multiple ranges / encoding / PDF text / hex | ops_inspect_local_file |
| Images | read_image (host) |
| Search contents | ops_grep |
| Find paths | ops_glob |
| Batch replacement; use host edit for precise edits | ops_replace |
| General commands / builds / git / pipelines / scripts — preferred command executor | ops_bash |
| Windows-native cmdlets / registry / services only | pwsh (bundled PowerShell 7 via host) |
```

这张表的实际含义：

- **只有声称了经评审等价物的行才会被隐藏**：`read` → `ops_inspect_local_file`、`glob` → `ops_glob`、`grep` → `ops_grep`。
- **平台保留的宿主 shell 永不隐藏**：Windows 上是 `pwsh`，其它平台是 `bash`，即使它就在 shell 面里。
- **在接管面内但保留可见**：`write`、`edit`、`str_replace_editor`、`run_code`，以及除保留 shell 之外的 shell 名称。它们会被警告逐个点名，调用依然可用——没有替代品就隐藏会造出官方/OPS 混用面。
- **接管范围外**：全部 `outside` 行与两个动态前缀。它们保留可见，并出现在同一条警告里，说明自己在 `shell/file/ptc` 之外。这正是标准桌面 profile 可以启用本行而不再触发 `READINESS_BLOCKED` 的原因（#207/#238）。
- **唯一的 fail-closed 情形**：`additionalOfficialTools` 点名了一个**没有等价物**的范围内工具。`READINESS_BLOCKED (HIDING_REQUEST_UNSATISFIABLE)` 会点名该工具，并给出两条可执行的出路（从 `additionalOfficialTools` 移除，或禁用该行）。

`scope` 决定接管范围有多宽；默认档 `takeover` 就是上面这张表，既有配置行的行为完全不变：

| `scope` | 隐藏什么 | `additionalOfficialTools` 点名 `outside` 工具时 | 警告 |
| --- | --- | --- | --- |
| `takeover`（默认） | 声称了经评审等价物的行 | 警告并忽略 | 一条汇总警告 |
| `extended` | 同上 | 提升进接管范围；没有等价物则该范围 fail-closed 并给出出路 | 对其余工具一条汇总警告 |
| `off` | 都不隐藏 | 静默忽略 | 无，也没有就绪门 |

三种模式可直接复制的配置行见[配置参考](配置参考.md)。
