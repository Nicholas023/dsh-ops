# 省钱思路·通用版（可迁移到任何 AI Agent）

> 本文档把「固定工具面+静态提示+批处理」的省钱方案抽象为**平台无关的方法论**，附带实测数据与避坑清单。DSH 安装版见同目录 cot-gw-static 预设与安装说明。

---

## 0. 先看懂账单（一切优化的镜子）

LLM 调用成本 = **未命中输入 × 全价 + 命中输入 × 折扣价 + 输出 × 输出价**（以 DeepSeek 为例：1.5 / 0.05 / 4.5 元每百万 token，命中价是未命中的 1/30）。

**三个反直觉事实（实测）**：
- 输出往往占总成本 60%+（价格 4.5 是注入的 3 倍、命中的 90 倍）——**别只盯着输入**；
- 命中率数字是过程指标：两端 96~97% 时，进一步调缓存收益≈0，**钱在未命中与输出**；
- 首步（新会话第一个请求）是单次最大未命中来源——**系统提示越小，首步越省**。

## 1. 四个杠杆（按收益排序）

**杠杆 A：精简系统提示（去掉"整本手册"）**
- 做法：把全局身份/规则/目录注入换成一段极简 persona（几百 token）；任务要求让用户写进消息（自包含）。
- 实测：首步未命中 6018 → 1236（**-79%**）。
- 注意：**别把"知识"剥光**——技能/工具清单保留**紧凑索引**（名+一句话），否则模型会为找东西反复搜索（实测 17 次空搜 = 更贵 + 质量降级）。

**杠杆 B：让请求前缀字节级稳定（吃满折扣价）**
- 做法：工具定义（schema）固定、不按会话变化；动态内容（时间戳/会话 ID/路径）移出前缀；同一前缀的会话多开。
- 实测：缓存命中率 96.8%（前缀稳定；跨会话共享前缀时首步即命中）。
- 注意：前缀 = 系统提示 + 工具定义 + 历史（尾部）。**工具面动态增删会破坏前缀**——要么固定、要么走"按需路由"（见 D）。

**杠杆 C：动作批处理（少付"每轮固定开销"）**
- 做法：提示词硬规则"无依赖的同类动作（多次写文件/重复查询）用一条脚本/一次调用完成；完成后简短确认"。
- 实测：十轮链任务 10 步 → 2 步；批量写 8 文件 -75%。
- 注意：批处理用**短指令**而非长代码（写长程序反而抬高输出，得不偿失）。

**杠杆 D：按需路由工具（能力常在、说明书不常驻）**
- 做法：注入面只留高频 N 个工具；其余经一个"网关"按需 list/describe/call（一次返回紧凑索引 + 参数按需取）。
- 实测：40+ 工具目录每次请求 9.35K 回填 → 紧凑索引 1~2K；全量能力仍可用（策略管线不绕过）。
- 注意：网关的目录输出要**紧凑**（名+首行用途），参数按需查——否则目录本身就吃掉你省的输入。

## 2. 迁移到其它 AI Agent 的对照表

| 本方案动作 | Anthropic / Claude | OpenAI / GPT | 本地/自托管 |
|---|---|---|---|
| 前缀稳定吃折扣 | Prompt Caching（5 分钟 TTL，前缀一致即命中） | 官方前缀缓存已自动（prompt 复用即命中） | 取决于服务商；vLLM 前缀缓存/对话轮次缓存 |
| 精简 persona | 系统提示压缩 + 角色固定 | system message 精简 | 同左 |
| 固定工具面 | tool 定义顺序/内容固定，动态工具走 router/agent 内调用 | functions 固定+按需注入 | 同左 |

| 熔断/预算 | 单任务 token 限额（如 5 万）自动中止 | 同左 | 同左 |

## 3. 避坑清单（做之前先读）

这些"优化"看起来好、实测是负收益：
- ❌ **继续剥系统提示**：省 0.007、赔 0.04（模型失明→反复搜索+质量降级），纯负收益；
- ❌ **追缓存命中率**：96%→97.5% 只差 0.7 个点，而命中单价只有未命中的 1/30，收益趋零；
- ❌ **压"每步未命中"**：拆更多步每步自然更小，总量/费用/延迟反而升高（分母游戏）；
- ❌ **降推理档换钱**：这是降天花板，不是体系变强；质量是你的底线。

## 4. 验证协议（怎么证明真的省了）

1. **端到端双基线**：同一组任务，原配置 vs 新配置各跑一遍（任务文本逐字一致、每任务独立新会话）；
2. **拆解**：记录每请求 未命中/命中/输出 三个数（不是只看总价）；
3. **分形态看**：批处理/文件/联网/看图/子代理/技能/长链——省钱往往集中在主习惯形态；
4. **两次复测**：费用差 <15% 才算稳定；
5. **质量守门**：新配置无 ✗；有 ⚠ 必须能解释并修复；
6. **参照系陷阱**：你的"原默认"可能已经是单伞形工具 + 高缓存（如 Code Mode）——此时"工具面更小"根本不是你的收益来源，别把功劳记错；
7. **预算红线**：预设计费上限（示例：单任务 >5 万 token 立即中止）。

## 5. 什么时候值得做、什么时候别做

- **值得**：每天开很多新会话、会话长（10+ 轮）、工具密集型（文件/脚本/子代理/看图）——收益与"频次 × 首步差 + 轮次数"成正比；
- **不值得**：少数短对话、纯聊天——省的不如折腾的成本；
- **收益预期参考**（本方案实测）：-47%（任务集口径）；若你的平台已同样高缓存，预期 10~30% 是现实的。
